# Stateful Application Migration Using Velero and Azure

This guide describes the end-to-end migration of a stateful application
from a local Minikube cluster to a cloud-based AKS cluster using Velero
and Azure Blob Storage.

------------------------------------------------------------------------

## 1. Install Local Tools

If these tools are not already installed on your computer, install them
(for example, with Homebrew on macOS):

``` bash
brew install minikube velero kubectl terraform azure-cli
```

## 2. Sign In to Azure

Before working with Azure resources, sign in to your Azure account:

``` bash
az login
```

This command opens a browser window where you can sign in.

## 3. Start and Configure the Local Cluster (Minikube)

Start the local cluster with the addons required to support persistent
volumes and volume snapshots:

``` bash
minikube start --addons=csi-hostpath-driver,volumesnapshots --driver=docker
```

Check the cluster status:

``` bash
minikube status
kubectl cluster-info --context minikube
```

## 4. Deploy the Infrastructure with Terraform

Navigate to the directory containing the Terraform configuration:

``` bash
cd velero-aks
```

Initialize Terraform and deploy the infrastructure:

``` bash
terraform init
terraform apply
```

Make sure your settings, including `owner`, are correctly configured in
`terraform.tfvars`.

## 5. Apply the Application Manifests in Minikube

Apply the application manifests (Namespace, ConfigMap, Deployment,
Service, and PVC) to the Minikube cluster.

If the manifests are stored in a separate `manifests/` directory:

``` bash
kubectl apply -f ../k8s/ --context minikube
```

Alternatively, apply the files individually:

``` bash
# kubectl apply -f namespace.yaml -f configmap.yaml -f deployment.yaml -f service.yaml -f pvc.yaml --context minikube
```

## 6. Install and Verify Velero in Minikube

Install Velero using the command generated by the Terraform output:

``` bash
$(terraform output -raw velero_install_minikube)
```

Check the backup storage location. The expected status is `Available`:

``` bash
velero backup-location get --kubecontext minikube
```

## 7. Create a Backup in Minikube

Create a backup of the `migration` namespace:

``` bash
velero backup create migration-backup --include-namespaces migration --kubecontext minikube
```

Verify the backup details, including the resources and volume data
captured:

``` bash
velero backup describe migration-backup --details --kubecontext minikube
```

## 8. Deploy to AKS and Restore the Application

Retrieve the credentials required to connect to AKS:

``` bash
$(terraform output -raw aks_get_credentials)
```

Install Velero in the AKS cluster:

``` bash
$(terraform output -raw velero_install_aks)
```

Restore the application from the backup created in Minikube. Replace
`<owner>` with your identifier:

``` bash
velero restore create --from-backup migration-backup --kubecontext aks-<owner>
```

## 9. Verify the Migration

### Check the Restore Status

Replace `<restore_name>` with the name of the restore operation:

``` bash
velero restore describe <restore_name> --kubecontext aks-<owner>
```

### Check Pods and Services in AKS

``` bash
kubectl get all -n migration --context aks-<owner>
```

### Verify Data on the Persistent Volume

The timestamp should match the value written in Minikube before the
backup was created:

``` bash
kubectl exec -it deployment/hellogo-deployment -n migration --context aks-<owner> -- cat /data/date.txt
```

### Verify the Web Interface

Forward the service port:

``` bash
kubectl port-forward svc/hellogo-service 8080:80 -n migration --context aks-<owner>
```

Open <http://localhost:8080> in your browser and verify that the
application displays its welcome message.

## 10. Clean Up the Environment

After completing the migration, remove the resources you created to
avoid unnecessary costs.

Uninstall Velero from Minikube:

``` bash
velero uninstall --kubecontext minikube --force
```

Delete the `migration` namespace from Minikube:

``` bash
kubectl --context minikube delete namespace migration
```

Destroy the cloud infrastructure with Terraform:

``` bash
cd velero-aks
terraform destroy
```

Remove the AKS context from `kubeconfig`:

``` bash
kubectl config delete-context aks-velero-<owner>
```

Verify that the Azure resource group has been deleted. The expected
result is `false`:

``` bash
az group exists --name rg-velero-<owner>
```
